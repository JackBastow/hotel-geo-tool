Guide

Schema markup for hotels: what to add.

Structured data says the facts about your hotel in a form machines can read. Here is what to include, how to check it, and what it won't do.

Updated {{ updated }} · 6 minute read

The short version

  • Schema markup (structured data) is code on a page that states facts about your hotel in a standard form that search engines and AI systems can read.
  • It can help accuracy and consistency. We have seen no good evidence that it makes an assistant recommend a hotel.
  • Only mark up what is true and visible on the page, and keep it in step with the page. Wrong structured data is worse than none.

The properties worth including

Use the schema.org type Hotel. These are standard fields; include the ones you can keep accurate.

PropertyWhat it saysNote
name, url, descriptionYour hotel's name, its web address and a short, factual description.Use the same name everywhere it appears.
addressA PostalAddress: street, town, postcode, country.Must match your map and booking-site listings exactly.
geoLatitude and longitude.Take them from a map you trust.
telephone, emailHow to reach the hotel.One number, the same on every page.
checkinTime, checkoutTimeCheck-in and check-out times.Frequent source of disagreement between listings.
petsAllowedWhether pets are allowed.Say the detail (fees, rules) in text on the page too.
amenityFeatureFacilities, as a list of named features (parking, pool, spa, EV charging, step-free access).List only what exists. Put the detail in text, such as the price of parking.
starRatingA rating from an official scheme, if you have one.Don't invent a rating.
numberOfRoomsHow many rooms.Optional.
priceRangeA rough guide to price.Optional. Keep it consistent with what you publish.
imageOne or more photos of the hotel.Use images that are on the page.
sameAsLinks to your official profiles: map listing, social pages, trade registers.Only profiles you actually control.

An example to adapt

This is a made-up hotel. Replace every value with your own, and delete anything that isn't true for you.

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Hotel",
  "name": "The Harbour Lane Hotel",
  "url": "https://www.example.com/",
  "description": "A 42-room hotel five minutes' walk from the cathedral, with free parking and breakfast from 7am.",
  "telephone": "+44 1234 567890",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "1 Harbour Lane",
    "addressLocality": "Brightmouth",
    "postalCode": "AB1 2CD",
    "addressCountry": "GB"
  },
  "geo": { "@type": "GeoCoordinates", "latitude": 50.0000, "longitude": -1.0000 },
  "checkinTime": "15:00",
  "checkoutTime": "11:00",
  "petsAllowed": true,
  "numberOfRooms": 42,
  "amenityFeature": [
    { "@type": "LocationFeatureSpecification", "name": "Free parking", "value": true },
    { "@type": "LocationFeatureSpecification", "name": "EV charging", "value": true }
  ],
  "sameAs": ["https://www.example.com/contact"]
}
</script>

What to avoid

  • Marking up things that aren't on the page or aren't true. Structured data should describe the page. If it disagrees with the page, the assistant has a reason to doubt both.
  • Marking up other people's reviews as your own. Review and rating markup has rules; read the search engine's guidelines before using it.
  • Setting it and forgetting it. When prices, times or facilities change, change the markup too.

How to check it

  1. Paste your page address into the Schema Markup Validator (validator.schema.org) to check the syntax.
  2. Use Google's Rich Results Test to see which Google features it supports.
  3. Read the page, then read the markup. Does every fact in the markup appear on the page, and agree with it?

What it does and doesn't do

Structured data can reduce errors, because the facts are stated in a form that does not depend on how a sentence was worded. We have seen no good evidence that it makes an assistant recommend a hotel, and nobody outside the AI companies knows how much weight any assistant gives it. Treat it as housekeeping: worth doing properly, not a shortcut. The same is true of llms.txt. For what is known and what is not, read how AI assistants choose hotels.

Common questions

Does schema markup make AI assistants recommend my hotel?

We have seen no good evidence that it does. Structured data states facts about a hotel in a machine-readable way, which can help accuracy and consistency. It is not a way to be recommended.

Which schema type should a hotel use?

Hotel, from schema.org, is the most specific type for a hotel. It is a kind of LodgingBusiness. Use the fields that describe real facts about your property and leave out the ones you cannot keep accurate.

How do I check my hotel's structured data?

Use the Schema Markup Validator at validator.schema.org to check the syntax, and Google's Rich Results Test to see which Google features it supports. Then compare the facts in the markup with the facts written on the page.
